# v0.1.0

First release of the offline quantitative research infrastructure. The examples and regression tests use synthetic daily prices and supplied corporate-action records.

## Included

- Deterministic daily-bar replay, with signals based on completed sessions and eligible orders simulated at a later observed open.
- Long-only, whole-share order execution and portfolio accounting, with cash, positions, fills, and commissions.
- SPY time-series momentum and short-term mean-reversion examples, buy-and-hold comparisons, and performance evaluation.
- Transaction-cost sensitivity and chronological research periods with separate warm-up and scoring windows.
- Stock-split and ordinary cash-dividend accounting in the daily backtest, plus split-aware strategy price history.
- Historical data integrity checks and an offline adapter for saved Massive daily aggregate responses.

## Limitations

Daily-bar execution is a simplified simulation with no real-money trading integration. The examples establish neither historical profitability nor verified empirical out-of-sample results. No proprietary market datasets are included.

Corporate-action handling depends on supplied terms. Standalone ledger callers must sequence accounting actions. The benchmark and chronological helpers remain price-only. A provider adjustment flag does not establish as-traded or point-in-time provenance.

## Rebuild and test on Windows

The verification environment is Windows x64 with CPython 3.11.9. Use PowerShell from the confirmed release checkout on D:. Dependency installation can use an index. The regression tests run offline. [Tested dependency constraints](../../constraints-windows-py311.txt)

```powershell
New-Item -ItemType Directory -Force .tmp\release-source, .tmp\release-temp, .cache\pip | Out-Null
$env:TEMP = (Resolve-Path .tmp\release-temp).Path
$env:TMP = $env:TEMP
$env:PIP_CACHE_DIR = (Resolve-Path .cache\pip).Path
$env:PYTHONDONTWRITEBYTECODE = '1'

git archive --format=tar --output=.tmp/release-source.tar HEAD
tar -xf .tmp/release-source.tar -C .tmp/release-source

python -m venv .tmp\release-build
$builder = '.\.tmp\release-build\Scripts\python.exe'
& $builder -m pip install build
& $builder -m build --outdir dist/rebuild .tmp/release-source

python -m venv .tmp\release-test
$testPython = '.\.tmp\release-test\Scripts\python.exe'
$wheel = (Resolve-Path dist\rebuild\event_driven_trading_research-0.1.0-py3-none-any.whl).Path
& $testPython -m pip install -c constraints-windows-py311.txt "${wheel}[dev]"
& $testPython -I -B -m pip check
& $testPython -I -B -m pytest -q -c .tmp/release-source/pyproject.toml .tmp/release-source/tests

Get-ChildItem dist/rebuild -File | Get-FileHash -Algorithm SHA256
```

Run the rebuild in a fresh checkout so the extracted tree contains only files from the release commit. The isolated build resolves setuptools according to `pyproject.toml`. Compare the distributed files with their recorded checksums. A new build can produce different archive bytes. [PyPA build usage](https://build.pypa.io/en/stable/how-to/basic-usage.html)
